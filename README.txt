# 我的桌曆記事本｜第二版

這是一個可以長期使用的「電子桌曆記事本」網站。

## 目前功能

- 自動使用手機/電腦目前年份與月份
- 不需要每年重新製作
- 目前開啟時會自動落在當月份；也可以左右切換月份
- 點選日期 → 整個記事視窗放大
- 輸入文字 → 即時儲存
- 關閉記事視窗 → 月曆格子顯示記事摘要
- 今天日期會特別標示
- 週末使用不同色調
- 手機版重新排版
- 匯出全部記事為 JSON 備份
- 匯入 JSON 備份
- 清除單日記事
- 清除全部記事
- PWA manifest
- Service Worker 離線快取
- 可安裝到手機桌面（正式 PWA 建議使用 HTTPS 網址）

## 最重要：記事到底存在哪裡？

本版本使用瀏覽器的 localStorage。

也就是：
「這一台裝置 + 這一個瀏覽器」的本機資料。

例如：
手機 Safari 裡存的記事，不會自動出現在另一台電腦 Chrome。

一般關閉網頁、重新開啟、重新啟動手機，都不會讓記事消失。

但如果使用者主動清除：
- Cookie
- 網站資料
- 網站儲存空間
- 瀏覽器的全部網站資料

則 localStorage 可能被刪除。

因此第二版特別加入：
「匯出備份 / 匯入備份」。

建議每隔一段時間匯出一次 JSON。

## 為什麼不用每年重新做？

完全不用。

程式會從裝置日期取得年份、月份、星期、每月天數。

所以：
2026 → 2027 → 2028 → 2029……
都會自動計算。

記事的日期 key 也是完整年月日，例如：
2026-10-08

所以跨年後，舊記事仍然可以保留。

## 如何在手機桌面使用？

### 最佳方式：PWA

要完整做到：
「手機桌面有一個圖示 → 點一下 → 像 App 一樣開啟」

建議把整個資料夾放到 HTTPS 網站空間。

然後手機開啟 index.html 所在的 HTTPS 網址。

Android Chrome：
瀏覽器選單 → 加到主畫面 / 安裝應用程式

iPhone Safari：
分享 → 加入主畫面

### 直接打開 HTML

如果目前只是要測試，可以直接雙擊 index.html。

桌機 Chrome / Safari 可以直接使用。

但 file:// 模式下，PWA Service Worker 通常不會啟用，
因此不會有完整的「安裝 App」效果。

### 關於「清除瀏覽記錄」

「清除瀏覽記錄」和「清除網站資料」不是完全同一件事。

本版本改成 IndexedDB 儲存，比單純 localStorage 更適合長期資料，但瀏覽器若執行「清除網站資料／Cookie／網站儲存空間」，仍可能把本機記事一起刪除。

因此：
- 只關閉網頁：記事在。
- 重新開機：記事在。
- 一般瀏覽歷史清除：通常不等於刪除 IndexedDB，但不同瀏覽器選項名稱可能不同。
- 清除「網站資料」：仍可能刪除記事。

如果你要求「即使把 Safari/Chrome 的網站資料全部清掉，記事仍 100% 保留」，單純網頁技術無法保證。要做到這個等級，需要把資料同步到雲端帳號/資料庫，或做成真正的原生 App 並使用 App 自己的資料庫。

### 假日同步

本版本使用公開 JSON 資料源同步台灣政府行政機關辦公日曆整理資料。資料源專案說明其資料來源為政府行政機關辦公日曆表，並會依政府新年度資料更新。實際放假適用對象仍以政府公告及你的工作身分為準；民間企業、學校等可能有不同規則。

若未來政府公布新的年度辦公日曆，網站有網路時可取得新年度資料；若該資料源尚未發布該年度，網站會使用既有資料/離線 fallback，等新資料發布後再同步。


## GitHub Pages 與「每個人自己的記事」

這個網站目前是「純前端 + 瀏覽器本機資料」。

所以即使把整個資料夾放到 GitHub Pages：

- 你自己的手機瀏覽器有你的記事
- A 使用者第一次開網站，有 A 自己的空白記事資料
- B 使用者第一次開網站，有 B 自己的空白記事資料
- A 不會因為網址相同而看到你的 IndexedDB
- B 也不會看到 A 的 IndexedDB

原因是 IndexedDB / localStorage 是「每個使用者自己的瀏覽器網站儲存空間」，不是 GitHub 上的共享檔案。

因此這種架構其實非常適合你目前說的需求：
「我做一個網站放 GitHub，任何人都可以打開，但每個人都記自己的事情。」

### 但是要注意

GitHub repository 裡的 HTML / CSS / JavaScript 程式碼如果是公開 repository，別人可以看到程式碼。
所以不要把密碼、API 金鑰、私人記事內容直接寫死在程式碼裡。

你的記事沒有寫進 GitHub 檔案；它是在使用者自己的瀏覽器 IndexedDB 裡。

### 如果以後改成雲端同步

那就不一樣了。

如果第四版把記事同步到雲端資料庫，就必須做：
- 使用者帳號 / 身分
- 每個使用者自己的資料區
- 權限控制
- 登入後只讀自己的記事

否則雲端資料庫才可能出現「大家看到同一份記事」的問題。

所以目前第三版其實是：
「公開網站 + 每個人自己的本機記事」
而不是：
「公開網站 + 大家共用同一份記事」。

資料以行政院人事行政總處 2027 年政府行政機關辦公日曆表為準。官方已核定 2027 年共 121 日放假，並列出 1/1、2/4-2/10、2/27-3/1、4/3-4/6、4/30-5/2、10/9-10/11、10/23-10/25、12/24-12/26，以及 2028 元旦補假 2027/12/31 等安排。

2028 年截至本版本製作時，行政院人事行政總處尚未公布正式辦公日曆表；官方規定次年辦公日曆原則上於每年 6 月 30 日前公告。因此本版本先依現行《紀念日及節日實施條例》與 2028 公曆/農曆日期加入「預估」標記。正式 2028 辦公日曆公布後，應以官方版本取代預估資料。
